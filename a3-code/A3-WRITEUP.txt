kmeans_cuda Discussion Questions
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

  Analyze your table of results and answer the following questions.
  1. Did using the GPU result in speedups?

    Yes, using the GPU resulted in a massive speedup.

  2. Describe your general approach on how you used GPU threads/blocks
     to parallelize the algorithm.
     - How did you subdivide the Cluster Center Calculation Phase?
     - How did you subdivide the Data Assignment Phase?

     I subdivided the cluster center calculation phase by making a block for each cluster
     and a thread for each dimention, and had each block interate through all the data points
     and have the thread update its respective dimension of that cluster if the data point it was
     on was assigned to that cluster. I found that this worked best because it removed the need for any
     synchronization or atomocization between the threads as they were all changing different parts 
     of the memory. This was made possible also because the problem fixed the size of the dimension of the data
     so that there would be enough threads in each block to have one thread per index of the dimension. Since 
     only one thread was assigned to each dimension, this approach also made what was previously an inner loop
     run in linear time.

     I subdivided the data assignment phase by first seeing how many data points there were. If the problem
     was small, I only created one block and assigned each thread to one of the datapoints. If the problem was
     larger, I used the appropriate number of blocks and had each one use 1000 threads, each thread still being 
     assigned to one datapoint. I thought this approach did well because it subdivied the outter loop which had 
     the most potential to scale as problem sizes got bigger. However, since there was no way of knowing which cluster
     the data point would get assigned to ahead of time, this approach required using atomoic add to augment the 
     count of each cluster, as well as the number of changes. I thought that this drawback would be minor though since
     the number of changes should decrease as the algorithm get closer and closer to converging, thus minimizing
     these drawbacks the further into the algorithm it got. This approach also had the plus side of not needing to
     atomicize the that data's cluster assignment, as each thread was operating  on a different data point. The atomic 
     add drawback of this approach would be much more of a problem if no convergence was found, as a pretty high number 
     of calls to atomicadd would occur in this situation.
